# 工程と成果物

LabOps（研究室統合プラットフォーム）の開発工程ごとの成果物一覧。
上流から下流へ、前工程の決定事項を次工程が引き継ぐ形で進めている。

| 工程 | 成果物 | 内容 | 状態 |
|---|---|---|---|
| 1. 要件定義 | [要件定義書](01_要件定義/要件定義書_研究室統合プラットフォーム.md) | 背景・対象範囲・機能要件（優先度4グループ）・非機能要件 | 確認済み（v1.0） |
| 2. 基本設計 | [基本設計書](02_基本設計/基本設計書_研究室統合プラットフォーム.md) | 全体アーキテクチャ・技術スタック選定・認証方針・画面構成・主要エンティティ | 確認済み（v1.0） |
| 3. 詳細設計 | [詳細設計書](03_詳細設計/詳細設計書_研究室統合プラットフォーム.md) | DBテーブル定義（13テーブル）・主要処理フロー・エンドポイント仕様 | 確認済み（v1.0） |
| 4. 実装 | ソースコード（リポジトリ全体） | Django + PostgreSQL + Docker Compose。詳細設計書2章の全テーブルをモデル化し、優先度①②の画面を実装 | 優先度②まで完了 |
| 4. 実装 | [起動手順書](04_実装/起動手順書_研究室統合プラットフォーム.md) | ローカルPC／研究室サーバーそれぞれの構築・起動手順、トラブルシューティング | v1.0 |
| 4. 実装 | [機能仕様書](04_実装/機能仕様書_研究室統合プラットフォーム.md) | 実装済み機能（優先度①②）の動作仕様、設計書との差分、既知の制約 | v2.10 |
| 4. 実装 | [管理サイト操作手順書](04_実装/管理サイト操作手順書_研究室統合プラットフォーム.md) | 管理サイトでのアカウント発行・NFCタグ管理・専用画面がない機能の運用手順 | v1.0 |
| 5. テスト | `accounts/tests.py`・`research/tests/`・`community/tests/` | モデル・ビュー・権限・htmxエンドポイントの単体テスト（299件） | 優先度②まで完了 |
| 6. リリース | `Dockerfile`・`docker-compose.yml`・`nginx/` | 研究室サーバーへの配備構成（nginx + gunicorn + PostgreSQL） | 構成のみ。実サーバーでの起動は未実施 |

## 工程間のトレーサビリティ

| 要件定義 | 基本設計 | 詳細設計 | 実装 |
|---|---|---|---|
| グループ1 研究支援系 | 研究支援の画面構成 | 2.3〜2.5（DiaryEntry / ScheduleEvent / ConferencePrep） | `research/` — 画面まで実装済み |
| グループ2 情報共有系 | 情報共有の画面構成 | 2.2 / 2.9 / 2.10（AttendanceStatus / CanteenMenu / NewsPost） | `community/` — 画面まで実装済み |
| グループ3 サーバー系 | サーバー管理の画面構成 | 2.6〜2.8（Server / ServerUsageSnapshot / ServerLongTermRequest） | `servers/` — モデルと管理画面のみ |
| グループ4 事務・その他 | 事務／キャリアの画面構成 | 2.11〜2.13（TravelExpenseRequest / Ticket / JobHuntingStory 他） | `office/` — モデルと管理画面のみ |

実装の優先順は要件定義書の優先度グループに準拠する（①研究支援系 → ②情報共有系 → ③サーバー系 → ④事務・その他）。

## 未確定事項の引き継ぎ

各工程で先送りにした判断は、担当工程で確定させる。

| 事項 | 決めた工程／先送り先 | 現状 |
|---|---|---|
| 技術スタック・ホスティング | 基本設計で決定 | Django / PostgreSQL / Docker Compose（研究室サーバー） |
| 認証方式 | 基本設計で決定 | メールアドレス＋パスワード。将来のSSO移行はバックエンド差し替えで対応 |
| パスワード変更・再設定画面 | 実装工程で保留 | 未実装。`/admin/` または `changepassword` で運用（起動手順書 3.5） |
| サーバー利用状況の収集方式 | 実装工程（優先度③）で確定 | 未着手。SSH／監視エージェント／手動報告のいずれか |
| 研究室HPとの連携方式 | 実装工程（優先度②）で保留 | 未確定。News記事の公開状態までは管理できるため、HP側への受け渡し方式のみ残る |
