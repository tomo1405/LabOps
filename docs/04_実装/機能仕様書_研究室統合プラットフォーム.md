## 2. 全機能に共通する仕様

### 2.1 認証とアクセス制御

| 項目 | 仕様 |
|---|---|
| 認証方式 | メールアドレス＋パスワード（Django標準のセッション認証） |
| ログイン画面 | `GET /login`。ログイン済みの状態で開くとダッシュボードへリダイレクト |
| ログアウト | `POST /logout`（ナビゲーションのボタン）。完了後はログイン画面へ |
| 未ログイン時 | 全画面が `/login?next=<元のURL>` へリダイレクトされる。ログイン後は元の画面へ戻る |
| アカウント発行 | サインアップ画面は設けていない。管理画面または `createsuperuser` で発行する |

ロールは「教員（faculty）」「学生（student）」の2種。**現時点ではロールによる画面の出し分けは行っていない**。
ロールを参照する承認操作が優先度③④の機能であり、まだ実装されていないため（[起動手順書 3.4](起動手順書_研究室統合プラットフォーム.md) 参照）。

### 2.2 参照範囲の原則

| データ | 参照できる人 | 更新できる人 |
|---|---|---|
| 研究日記 | 本人＋「研究室内に公開」された他メンバーの日記 | 作成者のみ |
| 学会準備・チェックリスト | 本人のみ | 本人のみ |
| 研究スケジュール | 本人の予定＋研究室共通予定＋自分が参加者に入っている予定 | 作成者（共通予定は全員が編集可）。参加者は閲覧のみ |
| 在室状況・入退室履歴 | 全員 | 自分の状態のみ |
| 学食メニュー | 全員 | 全員 |
| News記事 | 公開済みは全員、下書きは作成者のみ | 作成者のみ |

他人のデータを直接URL指定で開こうとした場合は **404** を返す（存在自体を知らせないため、403ではなく404）。

### 2.3 画面まわりの共通仕様

- レイアウトは全画面共通（ナビゲーション＋メッセージ表示領域＋見出し＋本文）
- 幅320px以上で横スクロールが発生しないことを確認している。狭い画面ではナビゲーションを折り返す
- **ヘッダーは画面上部に固定**（`position: sticky`）。下へスクロールしてもメニューが常に見える
- **現在地の表示**：開いている画面に対応するメニューを、背景の明るさとターコイズの下線で示す。
  詳細・編集・削除など下位の画面でも親メニューが選択状態のままになる
- 下位の画面には見出しの上にパンくず（例：研究日記 / 編集）を表示し、1クリックで一覧へ戻れる
- 保存・公開などの操作後は、画面上部に完了メッセージを1回だけ表示する
- 一覧系の画面は、該当データがない場合に「〜はありません」と明示する（空白のままにしない）

### 2.4 HTTPメソッドとCSRF

- 各エンドポイントは想定するメソッドのみ受け付ける。異なるメソッドでのアクセスは **405** を返す
- 通常のフォームは Django の CSRF トークンを埋め込む
- htmx によるリクエストは `hx-headers` で `X-CSRFToken` を送る

### 2.5 htmx を使う箇所

ページ全体を再読み込みせず、一部だけを差し替える。差し替え単位は次の4つ。

| 操作 | 差し替える範囲 |
|---|---|
| 学会準備のチェック切替 | チェックした項目1件のみ |
| 学会準備の項目追加 | そのチェックリスト全体 |
| 予定の追加 | カレンダーと予定一覧 |
| 在室状態の切替 | 在室ボード全体（自分の状態＋メンバー一覧＋在室人数） |

## 3. ダッシュボード

**目的**：ログイン直後に、自分の研究状況と研究室の共有情報をまとめて把握する。

**エンドポイント**：`GET /`

**表示内容**

| ブロック | 内容 | 件数 |
|---|---|---|
| 最近の研究日記 | 本人の日記（日付の新しい順） | 5件 |
| 今後の予定 | 現在時刻以降の予定（本人＋研究室共通） | 5件 |
| 学会準備の締切 | 本人の学会準備（締切の近い順）。進捗バー付き | 全件 |
| いま研究室にいる人 | 在室状態のメンバーのみ | 全員 |
| 本日の学食メニュー | 当日分。未登録なら「まだ登録されていません」 | 1件 |
| 研究室News | 公開済みの記事（新しい順） | 3件 |

**締切の強調表示**（詳細設計書3.5に対応）

| 状態 | 条件 | 表示 |
|---|---|---|
| 締切が近い | 残り0〜14日 | 警告色（黄）で強調 |
| 締切超過 | 締切日を過ぎている | グレー表示＋「（締切超過）」 |
| それ以外 | 残り15日以上 | 通常表示＋「（あと N 日）」 |

## 4. 優先度①：研究支援系

### 4.1 研究日記

**目的**：日々の研究内容・進捗・気づきを、日付単位で記録する。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/diary/` | 一覧（本人分） |
| GET/POST | `/diary/new` | 新規作成 |
| GET | `/diary/<id>` | 詳細 |
| GET/POST | `/diary/<id>/edit` | 編集 |
| GET/POST | `/diary/<id>/delete` | 削除（GETは確認画面、POSTで実行） |
| POST | `/diary/<id>/attachments` | 添付ファイルの追加 |
| GET | `/diary/<id>/attachments/<attachment_id>/file` | 添付ファイルの取得（認可付き配信） |
| POST | `/diary/<id>/attachments/<attachment_id>/delete` | 添付ファイルの削除 |
| POST | `/diary/<id>/like` | いいねの付け外し |
| POST | `/diary/<id>/comments` | コメントの投稿 |
| POST | `/diary/<id>/comments/<comment_id>/delete` | コメントの削除 |

**入力項目**

| 項目 | 必須 | 制約 | 補足 |
|---|---|---|---|
| 日付 | ○ | 日付形式 | 初期値は当日 |
| 本文 | ○ | 文字数上限なし | Markdownで記述できる |
| タグ | — | 200文字以内 | カンマ区切りで複数指定（例：`実験, 論文読み`） |
| 公開範囲 | ○ | 非公開／研究室内に公開 | 既定は非公開 |

**本文の書式（Markdown）**

- 見出し・箇条書き・強調・インラインコード・コードブロック・引用・表・リンクが使える
- 1行の改行はそのまま改行として表示する（研究メモの書き方に合わせた挙動）
- 保存されるのは入力したMarkdownそのもので、表示時にHTMLへ変換する
- **変換後のHTMLはサニタイズする**。`<script>`・`<iframe>`・`onerror` などのイベント属性・
  `javascript:` リンクは除去され、許可したタグと属性だけが残る
- 外部リンクには `rel="noopener noreferrer"` が付く

**公開範囲**

- 既定は**非公開**（自分だけが見られる）。作成・編集画面で「研究室内に公開」へ切り替えられる
- 一覧は「自分の日記」と「研究室の公開日記」の2つのタブに分かれる。
  前者は自分の記録だけ、後者は**公開設定にした日記だけ**（自分のものも含む）が並ぶ
- 公開した日記は他メンバーが詳細まで閲覧できるが、**編集・削除できるのは作成者のみ**。
  他メンバーの画面では編集・削除ボタンが表示されず、URLを直接指定しても404になる
- 非公開の日記を他メンバーが開こうとすると404

**動作仕様**

- 一覧の各行は、本文が長くても行の幅を超えず、収まらない部分は「…」で省略する
- 一覧の各行はクリックすると詳細へ移動する。日付のリンク表示・「詳細を見る →」・右端の
  シェブロン（›）・ホバー時の強調で、クリックできることを示している
- 一覧は日付の新しい順（同日なら作成日時の新しい順）に並ぶ
- 一覧上部の検索欄は**本文とタグの両方**を対象にしたキーワード検索。部分一致で、大文字小文字は区別しない
- 空白で区切って複数語を入れると、**すべての語を含む**記録に絞り込む（AND検索）
- 検索は表示中のタブの範囲内で行う。他メンバーの非公開日記が検索結果に出ることはない
- 絞り込み中は条件と件数を表示し、「クリア」で解除する
- 一覧の抜粋はMarkdown記法を取り除いた本文を表示する
- タグは1つの文字列として保存し、表示時にカンマで分割してバッジ表示する。前後の空白と空要素は除去される
- 保存後は作成した日記の詳細画面へ遷移する
- 他人の日記のIDを指定しても404となる

**いいね**

- 閲覧できる日記（自分のもの、または研究室内に公開された日記）に「いいね」を付けられる
- 同じボタンをもう一度押すと取り消す。1人につき1件までで、二重には数えない
- 詳細画面にいいね数と、いいねした人の名前を表示する。一覧では0件のとき何も出さない
- 自分の日記にも付けられる（読み返したときの目印として使えるため制限していない）
- 日記を削除すると、その日記のいいねも消える
- 他メンバーの非公開日記に付けようとすると404

**コメント**

- 閲覧できる日記（自分のもの、または研究室内に公開された日記）にコメントを書ける
- 投稿順に並び、投稿者名と投稿日時を表示する
- コメントを削除できるのは、**コメントの投稿者**と**日記の作成者**。それ以外は404
- 日記を削除するとコメントも一緒に削除される
- 非公開の日記では、実質的に本人だけがコメントできる（その旨を画面に表示する）

**添付ファイル**

- 詳細画面から、実験画像・グラフ・資料などを添付できる。1件の日記に複数添付できる
- 画像（PNG / JPEG / GIF / WebP）は本文の下に**そのまま表示**し、それ以外はダウンロードリンクになる
- 1ファイルあたり**10MB**まで
- 添付できる形式は、画像（PNG / JPEG / GIF / WebP）・PDF・Office文書（xlsx / docx / pptx）・
  データファイル（CSV / TSV / TXT / MD / JSON / ZIP）に限る。HTML・SVG・JavaScript などの
  能動的コンテンツは、同一オリジンでスクリプトが実行されるのを防ぐため受け付けない
- 拡張子だけでなくファイルの中身（シグネチャ）も検証する。クライアントが申告する
  Content-Type は判定に使わない
- 添付・削除ができるのは作成者のみ。公開された日記では、他メンバーは閲覧のみ
- 日記を削除すると添付も一緒に削除される。DBのレコードだけでなくファイルの実体も削除する
  （ユーザー削除・管理画面からの削除・一括削除でも同じ）
- ファイルの実体は `media/diary/<日記ID>/` に置くが、`/media/` は外部に公開しない。
  取得は必ず `GET /diary/<id>/attachments/<attachment_id>/file` を経由し、そこで
  ログイン状態と日記の公開範囲を検査する（非公開日記の添付が権限なしで取得されるのを防ぐ）
- 配信時の Content-Type は拡張子から決め、`X-Content-Type-Options: nosniff` を付ける。
  画像だけを `inline` で表示し、それ以外は必ずダウンロードさせる
- 本番では、認可判定後に `X-Accel-Redirect` で nginx（`internal` な `/media/`）へ実体配信を委譲する

**編集・削除**

- 詳細画面の「編集」「削除」ボタンから操作する
- 編集フォームには現在の値が入った状態で開き、日付・本文・タグをいずれも変更できる。
  保存すると更新日時が更新され、詳細画面へ戻る（新しい日記は作られない）
- 削除は確認画面をはさむ。確認画面を開いただけでは削除されず、「削除する」を押して初めて削除される
- 削除後は一覧へ戻る。削除した日記は復元できない
- 他人の日記を編集・削除しようとすると404

**制約**：同じ日付に複数件の記録を作成できる（1日1件の制限はかけていない）。

### 4.2 研究スケジュール

**目的**：研究計画のマイルストーンとタスクを、月単位のカレンダーで管理する。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/schedule/?view=&date=` | カレンダー（`view` は month / week / day、`date` は基準日） |
| POST | `/schedule/events` | 予定の追加（htmx） |
| GET/POST | `/schedule/events/<id>/edit` | 予定の編集 |
| GET/POST | `/schedule/events/<id>/delete` | 予定の削除（GETは確認画面、POSTで実行） |

**入力項目**

| 項目 | 必須 | 制約 | 補足 |
|---|---|---|---|
| タイトル | ○ | 100文字以内 | |
| 開始日時 | ○ | 日時形式 | |
| 終了日時 | — | 開始日時以降 | 未入力可（マイルストーンなど） |
| 種別 | ○ | 予定／タスク／マイルストーン | 既定は「予定」。種別ごとに色分けして表示する |
| 関連する学会準備 | — | 本人の学会準備のみ選択可 | 未選択可 |
| 参加者 | — | 自分以外の有効なメンバーから複数選択 | 選んだ人のスケジュールにも表示される |
| 研究室共通の予定にする | — | チェックボックス | チェック時は担当者を空にする |

**種別**

| 種別 | 用途 | 表示 |
|---|---|---|
| 予定 | 打ち合わせ・面談・ゼミなど、時間が決まっているもの（既定） | 青 |
| タスク | 期間内に進める作業 | 緑 |
| マイルストーン | 締切や提出など、その時点を示すもの | 黄（一覧では強調） |

**表示単位（月・週・日）**

- 画面左上の「月 / 週 / 日」で切り替える。既定は月表示
- 「前へ / 今日 / 次へ」は表示単位に合わせて移動する（月表示なら1か月、週表示なら7日、日表示なら1日）
- 月表示は**日曜始まり**のグリッド。日付をクリックするとその日の日表示へ移動する
- 週表示は日曜〜土曜の7列、日表示は1日分を時刻順に並べる。当日は枠とヘッダーの色で強調する
- 週表示は列が狭いため、「今日」バッジを出さず、参加者は人数のみ表示する（氏名は日表示と一覧で確認する）。
  長いタイトルや作成者名は列内で折り返す・末尾を省略することで、列の高さが揃うようにしている
- 週表示で予定が多い日は、列の中だけを縦スクロールさせる
- カレンダー下部に、表示中の期間の予定を開始日時順で一覧表示する
- `date` に不正な値を渡すと404（旧来の `year` / `month` 指定にも対応しており、こちらも不正なら404）

**参加者（他メンバーへの反映）**

- 予定に参加者を指定すると、**その人のスケジュールとダッシュボードにも同じ予定が表示される**
- 参加者の一覧は予定の一覧・カレンダーに表示される。他メンバーの予定には作成者名のバッジが付く
- 参加者に追加されただけの人は**閲覧のみ**で、編集・削除はできない（作成者と共通予定は従来どおり）
- 参加者の候補は自分以外の有効なメンバー。作成者は常に予定の関係者となるため候補から外している
- 自分の予定に自分を参加者として入れても、一覧に重複表示されない

**動作仕様**

- 表示対象は「本人の予定」＋「研究室共通予定（担当者なし）」＋「自分が参加者の予定」
- 共通予定には「研究室共通」バッジが付く
- 追加は htmx で行い、**表示単位を保ったまま**、作成した予定が含まれる期間に差し替わる
- 終了日時が開始日時より前の場合はエラーとなり、入力内容を保持したままエラーメッセージを表示する（HTTP 400）

**編集・削除**

- 予定一覧の各行にある「編集」から操作する。削除は編集画面の「削除」ボタンから確認画面へ進む
- 本人の予定に加えて、**研究室共通の予定は全メンバーが編集・削除できる**
  （共通予定は誰でも作成できる設計に合わせている）。他メンバーの個人予定は、参加者であっても404
- 編集画面で「研究室共通の予定にする」を切り替えると、個人予定と共通予定を相互に変更できる
- 保存・削除後は、その予定が属する月のカレンダーへ戻る

**制約**：繰り返し予定、通知は未実装。

### 4.3 学会準備支援

**目的**：学会ごとの締切と、提出までにやることをチェックリストで管理する。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/conference/` | 一覧（本人分） |
| GET/POST | `/conference/new` | 学会の登録 |
| POST | `/conference/<id>/checklist` | チェック項目の追加（htmx） |
| POST | `/conference/<id>/checklist/<item_id>/toggle` | チェックの切替（htmx） |
| POST | `/conference/<id>/checklist/<item_id>/delete` | チェック項目の削除（htmx） |
| GET/POST | `/conference/<id>/edit` | 学会名・締切日の編集 |
| GET/POST | `/conference/<id>/delete` | 学会準備の削除（GETは確認画面、POSTで実行） |

**入力項目（登録時）**

| 項目 | 必須 | 制約 | 補足 |
|---|---|---|---|
| 学会名 | ○ | 100文字以内 | |
| 締切日 | ○ | 日付形式 | |
| チェックリスト項目 | — | 1行に1項目 | 空行は無視。後から追加も可能 |

**動作仕様**

- 一覧は締切の近い順。各学会に締切までの残日数、完了率（進捗バー）、チェックリストを表示する
- 完了率は「完了項目数 ÷ 全項目数」を四捨五入した整数。項目が0件のときは0%
- チェックボックスを操作すると、その項目だけが即座に差し替わる（ページ遷移なし）
- 項目を追加すると、その学会のチェックリスト全体が差し替わる
- 他人の学会準備・チェック項目を操作しようとすると404

**編集・削除**

- 一覧のヘッダーにある「編集」から学会名・締切日を変更する。削除は編集画面の「削除」ボタンから確認画面へ進む
- 編集画面のチェックリスト項目欄に入力した項目は、**既存のリストに追加**される（置き換えではない）
- 学会準備を削除すると、チェックリスト項目も一緒に削除される。
  **紐付けていた予定は削除されず、学会への紐付けだけが解除される**
- チェック項目は各行の「削除」から個別に削除できる（確認ダイアログあり、その場でリストが差し替わる）
- 他人の学会準備・チェック項目を編集・削除しようとすると404

**制約**：締切通知（メール等）は未実装で、強調表示は画面表示時の日付比較で判定する。

## 5. 優先度②：情報共有・コミュニケーション系

### 5.1 在室メンバー可視化

**目的**：いま誰が研究室にいるかを一目で把握する。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/attendance/` | メンバー一覧と在室人数 |
| POST | `/attendance/toggle` | 自分の在室状態の切替（htmx） |
| GET | `/attendance/history` | 入退室履歴（メンバー・期間で絞り込み） |
| GET | `/attendance/nfc/<token>` | NFCタグからの入退室登録（**ログイン不要**） |

**動作仕様**

- 有効なユーザー全員を一覧表示する。各行に氏名・ロール・在室／不在・最終更新時刻を示す
- ヘッダーに「在室 N / 全 M 人」を表示する
- 在室状況のレコードを一度も作成していないメンバーは**不在**として扱う（初回の切替時にレコードが作られる）
- 切替ボタンは常に自分の状態のみを対象とする。他人の状態は変更できない
- 切替は在室 ⇄ 不在のトグルで、押すたびに反転する。更新時刻もあわせて更新される
- 切替後は在室ボード全体（自分の状態・人数・一覧）が差し替わる

**入退室履歴**

- 在室状態を切り替えるたびに履歴を1件記録する（誰が・いつ・入室か退室か・どこから登録したか）
- `/attendance/history` で全メンバーの履歴を閲覧できる。研究室の共有情報として全員に公開する
- 既定の表示期間は**直近7日**。メンバーと期間で絞り込める。日付が不正な場合は既定の期間に戻す（404にしない）
- 「日ごとの在室時間」を、入室→退室の対から集計して表示する。
  **対になっていない記録（打刻漏れ）は集計から除き**、退室がまだの区間は「在室中」と表示する
- 表示件数の上限は300件。超える場合は期間を狭めるよう画面で案内する

**NFCタグからの登録**

- タグは**メンバーごとに発行**する。1人が複数枚持つこともできる（入り口用・予備など）
- タグに書き込んだURLを開くと、**ログインなしでそのメンバーの在室／不在が反転する**。
  かざすだけで打刻が完了し、画面には氏名と反転後の状態が表示される
- 同じメンバーの打刻が**30秒以内**に続いた場合は反転させない。
  かざし直しやブラウザの先読みで、入室直後に退室扱いになるのを防ぐため
- 打刻結果のページはキャッシュしない（`Cache-Control: no-store`）
- 存在しないトークン・無効化したタグは404。POSTは受け付けない（405）
- 対象メンバーを削除すると、そのメンバーのタグも削除される

**タグの発行と運用（管理者）**

- 発行は管理画面（`/admin/` → NFCタグ）でのみ行う。対象メンバーを選ぶとURLが表示される
- 紛失・流出したタグは、一覧から選んで「トークンを再発行する」を実行すると**古いURLが使えなくなる**。
  「無効にする」で一時的に止めることもできる

> **運用上の注意**：この方式では**URLそのものが打刻の鍵**になる。URLを知っていれば
> 誰でもそのメンバーの在室状態を切り替えられるため、タグの管理と配布先に注意する。
> トークンは推測できない値を自動生成しており、URLで行えるのは在室状態の切替のみで、
> ログインや他のデータの閲覧はできない。

**制約**：センサーによる**自動検知は行わない**（ビーコン、Wi-Fi、入館ログ等）。
NFCタグはかざす操作で打刻を済ませるためのもので、在室しているかどうかの判定自体は行わない。
「◯時に退室予定」のような予定情報も扱わない。

### 5.2 学食メニュー共有

**目的**：その日の学食メニューを研究室内で共有する。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/canteen/today` | 本日のメニューと直近の登録履歴 |
| POST | `/canteen/` | メニューの登録 |
| GET/POST | `/canteen/<id>/edit` | 登録済みメニューの編集 |
| GET/POST | `/canteen/<id>/delete` | 登録済みメニューの削除（GETは確認画面、POSTで実行） |

**入力項目**

| 項目 | 必須 | 制約 | 補足 |
|---|---|---|---|
| 日付 | ○ | 日付形式・1日1件 | 初期値は当日 |
| メニュー内容 | ○ | 文字数上限なし | 改行はそのまま表示される |

**動作仕様**

- 画面上部に当日のメニューを表示する。未登録の場合はその旨を表示する
- その下に、当日を除く直近7件を新しい順で表示する
- **同じ日付を再登録した場合はエラーにせず、内容を上書きする**（日付は一意のため。運用中の修正を想定）
- 登録・更新のいずれかをメッセージで区別して通知する
- 入力に不備がある場合は入力内容を保持したまま再表示する（HTTP 400）
- 取得元は「手動登録」で固定。自動取得（`scraped`）の区分はデータ構造として用意しているが、取得処理は未実装

**編集・削除**

- 本日のメニューと履歴の各行に「編集」がある。削除は編集画面の「削除」ボタンから確認画面へ進む
- 編集で日付を**既に登録済みの日**に変更した場合は、その日の登録を置き換える（重複は作らない）
- 誰でも編集・削除できる（研究室の共有情報として扱うため）

**制約**：誰が登録したかは記録しない（データ構造上、登録者を持たない）。
そのため編集・削除の権限もメンバー間で区別していない。

### 5.3 研究室HP News投稿

**目的**：研究室公式サイトに載せるお知らせを、下書き→公開の流れで管理する。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/news/` | 一覧 |
| GET/POST | `/news/new` | 新規投稿（下書き保存／公開） |
| POST | `/news/<id>/publish` | 下書きの公開 |
| POST | `/news/<id>/unpublish` | 公開の取り下げ（下書きへ戻す） |
| GET/POST | `/news/<id>/edit` | 記事の編集 |
| GET/POST | `/news/<id>/delete` | 記事の削除（GETは確認画面、POSTで実行） |

**入力項目**

| 項目 | 必須 | 制約 |
|---|---|---|
| タイトル | ○ | 200文字以内 |
| 本文 | ○ | 文字数上限なし |

**動作仕様**

- 投稿フォームには「下書き保存」と「公開する」の2つの送信ボタンがある。押したボタンで保存後の状態が決まる
- 公開すると、そのときの日時が公開日時として記録される
- 一覧には「公開済みの全記事」と「自分の下書き」が並ぶ。他人の下書きは表示されない
- 並び順は公開日時の新しい順で、未公開の下書きを先頭に置く
  （NULLの並び位置はPostgreSQLとSQLiteで既定が逆になるため、モデル側で明示指定している）
- 自分の下書きには「公開する」ボタンが表示される。他人の記事には表示されない
- **公開済みの記事に対して再度公開操作を行っても、公開日時は上書きされない**
- 他人の下書きを公開しようとすると404

**編集・取り下げ・削除**

- 一覧の各記事（自分のもの）に「編集」と、状態に応じて「公開する」または「下書きに戻す」が表示される
- **公開済みの記事を編集しても、公開状態と公開日時は変わらない**（訂正を想定）
- 「下書きに戻す」で公開を取り下げると、状態が下書きに戻り公開日時は消える。
  再度公開すると、そのときの日時が新たに記録される
- 削除は編集画面の「削除」ボタンから確認画面へ進む。
  公開中の記事は、掲載を止めるだけなら削除ではなく取り下げを使う旨を確認画面で案内する
- 他人の記事を編集・削除・取り下げしようとすると404

**制約**：**研究室HP側への受け渡し方式は未確定**で、現時点では本システム内で公開状態を管理するのみ。

## 8. 詳細設計書との差分

実装にあたって、詳細設計書4章のエンドポイント一覧に**追加した経路**が20ある。
いずれも設計書の処理フロー（3章）を成立させるために必要だったもので、削除・変更した経路はない。

| 追加した経路 | 理由 |
|---|---|
| `GET/POST /conference/new` | 詳細設計書3.5の手順1「学会名・締切日・チェックリスト項目を登録」に対応する画面が一覧になかったため |
| `POST /conference/<id>/checklist` | 同上。登録後にチェック項目を追加する手段がなかったため |
| `POST /news/<id>/publish` | 詳細設計書3.7の手順2「内容確定後に公開操作」に対応する経路が一覧になかったため |
| `GET/POST /diary/<id>/edit` | 記録の訂正手段が一覧になく、CRUDのUpdateが成立しなかったため |
| `GET/POST /diary/<id>/delete` | 同上。誤って作成した記録を取り消せなかったため |
| `GET/POST /schedule/events/<id>/edit` | 予定の変更手段が一覧になかったため |
| `GET/POST /schedule/events/<id>/delete` | 中止になった予定を取り消せなかったため |
| `GET/POST /conference/<id>/edit` | 学会名・締切日の変更手段が一覧になかったため |
| `GET/POST /conference/<id>/delete` | 終わった学会・誤登録を取り消せなかったため |
| `POST /conference/<id>/checklist/<item_id>/delete` | 不要になったチェック項目を消せなかったため |
| `GET/POST /news/<id>/edit` | 誤字の訂正など、記事の修正手段が一覧になかったため |
| `GET/POST /news/<id>/delete` | 不要になった記事を消せなかったため |
| `POST /news/<id>/unpublish` | 掲載を止める手段が公開の一方向しかなかったため |
| `GET/POST /canteen/<id>/edit` | 当日以外のメニューを直す手段がなかったため |
| `GET/POST /canteen/<id>/delete` | 誤登録したメニューを消せなかったため |
| `POST /diary/<id>/attachments` ほか1件 | 実験画像・資料を記録に残せなかったため |
| `POST /diary/<id>/comments` ほか1件 | 公開した日記に助言・質問を書く手段がなかったため |
| `POST /diary/<id>/like` | 公開した日記に、コメントより軽い反応を返す手段がなかったため |

また `GET /canteen/today` は、設計書では「本日の学食メニュー取得」とされていたが、
**画面として実装**した（登録フォームと履歴を同じ画面に置いた）。JSONを返すAPIではない。

## 10. テストによる仕様の裏付け

本書に記した動作は、単体テスト72件で検証している（`accounts/tests.py`、`research/tests/`、`community/tests/`）。

| 観点 | 主な検証内容 |
|---|---|
| 認証 | 未ログイン時のリダイレクト先、ログイン後の遷移、ロールの既定値 |
| 参照範囲 | 他人のデータが一覧に出ないこと、直接アクセスが404になること |
| 入力検証 | 必須項目の未入力、終了日時が開始日時より前の場合 |
| 状態遷移 | 在室のトグル、下書き→公開、公開日時が上書きされないこと |
| 一意制約 | 同日の学食メニューが上書きになること、在室状況が1人1件であること |
| HTTPメソッド | 想定外のメソッドが405になること |
