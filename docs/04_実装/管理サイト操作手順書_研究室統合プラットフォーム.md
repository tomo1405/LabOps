管理サイトは Django 標準の管理画面（`django.contrib.admin`）である。本書はそこに登録した
モデルと、運用で必要になる操作の手順をまとめる。アプリ側の画面操作は対象外。

---

## 2. アクセス方法

| 項目 | 内容 |
|---|---|
| URL | `http://<サーバーのホスト名>/admin/`（ローカルは <http://127.0.0.1:8000/admin/>） |
| 導線 | アプリ画面右上の「管理画面」ボタン（権限のある人にだけ表示される） |
| ログイン | アプリと同じメールアドレス・パスワード |

### 2.1 入れる人

**「管理画面利用可」（`is_staff`）を持つユーザーだけ**が利用できる。
アプリ内のロール（教員／学生）とは別の権限である点に注意する。

持っていないアカウントでアクセスすると、次のように表示されてログイン画面へ戻される。

> あなたは ○○ として認証されましたが、このページへのアクセス許可がありません。

この場合はログイン画面に管理者アカウントを入力し直すか、アプリ側でログアウトしてから開く。

### 2.2 最初の管理者を作る

管理者アカウントが1つもない場合は、サーバー上でコマンドから作成する。

```bash
python manage.py createsuperuser
```

作成されるユーザーは**教員ロール・管理画面利用可・全権限**となる。
以降のアカウント発行は管理サイトから行える。

## 3. 画面の構成

トップページに5つの区分が並ぶ。各区分の中に扱えるデータが並ぶ。

| 区分 | 扱えるデータ | 専用画面 |
|---|---|---|
| 認証・ユーザー管理 | ユーザー | ログインのみ |
| 研究支援 | 研究日記、学会準備、研究スケジュール | あり |
| 情報共有・コミュニケーション | 在室状況、NFCタグ、入退室履歴、会議室、会議室の予約、学食メニュー、News記事 | あり |
| サーバー利用状況・申請 | サーバー、利用状況スナップショット、長期利用申請 | **なし（管理サイトで運用）** |
| 事務・その他 | 出張費申請、チケット、就活体験記、OB訪問予約 | **なし（管理サイトで運用）** |

共通の操作は次のとおり。

- 一覧の列見出しをクリックすると並べ替えられる
- 右側の絞り込み欄で条件を絞れる
- 一部の画面には検索欄と、日付での絞り込み（年→月→日）が付く
- チェックボックスで複数選択し、上部のプルダウンから一括操作（アクション）を実行できる

## 4. アカウントの管理

**場所**：認証・ユーザー管理 → ユーザー

一覧にはメールアドレス・表示名・ロール・有効・登録日時が並ぶ。ロール、有効、管理画面利用可で絞り込め、
メールアドレスと表示名で検索できる。

### 4.1 アカウントを発行する

1. 右上の「ユーザーを追加」
2. メールアドレス（ログインIDになる）、表示名、ロール、パスワードを入力して保存
3. 発行したメールアドレスと初期パスワードを本人に伝える

**ロールの選び方**

| ロール | 用途 |
|---|---|
| 教員 | 承認操作を伴う機能（サーバー長期利用申請・出張費申請）を扱う人 |
| 学生 | 上記以外のメンバー |

### 4.2 パスワードを再設定する

対象ユーザーの編集画面を開き、パスワード欄の案内リンクから変更する。
アプリ側にパスワード変更・再設定の画面はないため、**忘れた場合はここで再設定する**。

サーバー上でコマンドからも変更できる。

```bash
python manage.py changepassword <メールアドレス>
```

### 4.3 管理サイトの権限を与える

編集画面の「権限」で設定する。

| 項目 | 意味 |
|---|---|
| 有効 | 外すとログインできなくなる（**退職・卒業時は削除ではなくこれを外す**） |
| 管理画面利用可 | 管理サイトに入れるようになる |
| スーパーユーザー | すべてのデータを操作できる |

> **削除より無効化を選ぶ**：ユーザーを削除すると、その人の研究日記・学会準備・予定・
> 入退室履歴・NFCタグもまとめて消える。在籍しなくなっただけなら「有効」を外す。

## 5. NFCタグの発行と管理

**場所**：情報共有・コミュニケーション → NFCタグ

在室状態を切り替えるためのタグを、メンバーごとに発行する。
**URLを開くとログインなしで在室／不在が反転する**ため、URLそのものが打刻の鍵になる。

### 5.1 発行する

1. 「NFCタグを追加」
2. **対象メンバー**を選ぶ（名称・設置場所は任意。「入り口用」「予備」など）
3. 保存すると「タグに書き込むURL」が表示される（トークンは自動生成のため入力不要）
4. 表示されたURLに**サーバーのホスト名を前置**して、NFCタグに書き込む

```
http://<サーバーのホスト名>/attendance/nfc/<トークン>
```

1人に複数枚（入り口用・予備など）発行できる。

### 5.2 URLを確認する

一覧に「タグに書き込むURL」列があるので、そのままコピーできる。
対象メンバー・有効/無効で絞り込め、氏名やメールアドレスで検索できる。

### 5.3 紛失・流出したとき

一覧で対象のタグを選び、上部のアクションから実行する。

| アクション | 効果 |
|---|---|
| トークンを再発行する | **新しいURLに差し替わり、古いURLは即座に無効になる（404）** |
| 無効にする | URLはそのままで打刻だけ止まる。編集画面で「有効」に戻せば再開できる |

再発行したあとは、**タグに新しいURLを書き込み直す**必要がある。

## 6. 会議室を登録する

**場所**：情報共有・コミュニケーション → 会議室

研究室の4部屋（全体ミーティングルーム B307／ミーティングルーム B303／
サーバルーム B304／ゲームルーム B305）は**初期データとして登録済み**のため、
通常は追加作業は不要。

部屋が増えたときは次の手順で追加する。

1. 「会議室を追加」
2. 名称と場所（部屋番号）を入力。定員は任意。
   **場所を入れると「名称（部屋番号）」の形で画面に表示される**。
   「並び順」は小さいほど先に表示される（既定の4部屋は0〜3を使用）
3. 保存すると、在室ページの予約フォームに選択肢として現れる

一時的に使えなくする場合は「利用可」を外す。既存の予約は残るが、新規予約の選択肢から消える。
会議室を削除すると、**その会議室の予約もまとめて削除される**ため、
使わなくなっただけなら「利用可」を外す。

予約自体（情報共有・コミュニケーション → 会議室の予約）も管理サイトから追加・修正・削除できる。
ただし**管理サイトでは時間の重なりを検査しない**ため、重複しないか自分で確認する。

## 7. 入退室の記録を確認・訂正する

**場所**：情報共有・コミュニケーション → 入退室履歴／在室状況

- **入退室履歴**：日時・メンバー・入室/退室・登録元（画面から／NFCタグ）が並ぶ。
  種別・登録元・メンバーで絞り込め、日付でも絞り込める。
  打刻漏れや誤記録は、ここで追加・修正・削除できる
- **在室状況**：現在の状態（在室／不在）。履歴とは別に保持しているため、
  **履歴を直しても現在の状態は変わらない**。必要なら両方を直す

なお、閲覧するだけならアプリの「在室メンバー → 入退室履歴」の方が見やすい。

## 8. 専用画面がない機能の運用

サーバー系と事務系には専用画面がないため、当面は管理サイトで登録・参照する。

### 8.1 サーバー利用状況・申請

| データ | 用途 |
|---|---|
| サーバー | 研究室／学科サーバーのマスタ。名称・種別・設置場所を登録する |
| 利用状況スナップショット | CPU・メモリ・ディスク・GPU使用率の記録。収集バッチは未実装のため、当面は手入力 |
| 長期利用申請 | 申請内容と承認状況。**承認するときは、ステータスに加えて承認者と承認日時も入力する** |

### 8.2 事務・その他

| データ | 用途 |
|---|---|
| 出張費申請 | 申請内容と承認状況。承認時は承認者もあわせて入力する |
| チケット | 開発リクエスト。コメントは同じ画面の下部でまとめて編集できる |
| 就活体験記／OB訪問予約 | 任意機能。登録・参照のみ |

## 9. 研究支援・情報共有のデータを直す

利用者が自分で直せない場合の代行や、誤登録の修正に使う。

| データ | 補足 |
|---|---|
| 研究日記 | 添付ファイルとコメントを同じ画面の下部で編集できる。いいね数も一覧に出る |
| 学会準備 | チェックリスト項目を同じ画面の下部で編集できる |
| 研究スケジュール | 担当者が空の予定は「研究室共通」として全員に表示される |
| 学食メニュー | 日付ごとに1件。献立は品目（定食・アラカルト丼）を下部で編集する |
| News記事 | ステータスを「公開」にする場合は、公開日時もあわせて入力する |

> **公開範囲に注意**：研究日記には「非公開」のものが含まれる。
> 管理サイトからは本人以外の非公開日記も閲覧できるため、必要な場合に限って開く。

---

## 10. 注意事項

- 管理サイトは**アプリ側の入力チェックを一部通らない**。日付の前後関係やステータスと
  承認者の整合など、画面側で担保している内容は手入力時に自分で確認する
- 削除は取り消せない。特にユーザーの削除は関連データを巻き込むため、無効化で足りないか確認する
- 操作履歴は各データの編集画面の「履歴」で確認できる（誰がいつ変更したか）
- 管理サイトは学内ネットワークからのみアクセスできる構成を前提とする（[起動手順書](起動手順書_研究室統合プラットフォーム.md) 4章）
