# 研究室統合プラットフォーム 要件定義書

| 項目 | 内容 |
|---|---|
| 文書名 | 研究室統合プラットフォーム 要件定義書 |
| 作成日 | 2026年9月3日 |
| バージョン | 1.0 |
| ステータス | 依頼者確認済み・承認待ち |

## 2. 背景・目的

研究室運営に関わる複数の業務（研究活動の記録、サーバー資源の管理、情報共有、事務手続き等）が個別のツールや手作業に分散しており、非効率が生じている。本プロジェクトでは、これらを一つの統合プラットフォームにまとめ、研究室内の情報流通と業務効率を高めることを目的とする。

## 3. 対象範囲

### 3.1 対象とする利用者

- 自身の研究室に所属する学生・教員
- 想定利用人数：10〜30人程度

### 3.2 対象外とする範囲（初期スコープ外）

- 学科内の他研究室、学科全体での共同利用
- 将来的な拡張の可能性は排除しないが、初期段階では自研究室内利用に限定する

### 3.3 開発体制・進め方

| 項目 | 内容 |
|---|---|
| 開発者 | 本人一人による開発 |
| 開発方針 | 優先度は設けつつも、全機能を見据えた全体設計を先に固めてから実装に着手する |
| 期限 | 特になし（継続的に機能拡張していく前提） |

## 4. 機能要件

優先度順に4グループへ整理する。各グループ内の機能の実装順は基本設計以降で調整する。

### グループ1：研究支援系（最優先）

| 機能 | 概要 |
|---|---|
| 研究日記 | 日々の研究内容・進捗・気づきを記録する |
| 研究スケジュール作成支援 | 研究計画・マイルストーンの作成と管理を支援する |
| 学会準備支援 | 学会発表に向けた準備（締切管理、資料準備等）を支援する |

### グループ2：情報共有・コミュニケーション系

| 機能 | 概要 |
|---|---|
| 研究室在室メンバー可視化 | 誰が今研究室にいるかを可視化する |
| 学食の今日のメニュー共有 | 学食の本日のメニュー情報を共有する |
| 研究室HPのNews投稿フォーム | 研究室公式サイトへのお知らせ投稿を支援する |

### グループ3：サーバー利用状況・申請系

| 機能 | 概要 |
|---|---|
| 研究室サーバ利用状況可視化 | 研究室サーバのリソース利用状況を可視化する |
| 研究室サーバ長期利用申請 | サーバーの長期利用申請・承認フローを電子化する |
| 学科サーバ使用状況可視化 | 学科サーバの利用状況を可視化する |

### グループ4：事務・その他（優先度低）

| 機能 | 概要 |
|---|---|
| 出張費申請フォーム | 出張費の申請を電子化する |
| 開発シェアアプリ（チケット形式） | ほしいシステム・機能をチケットとして共有・管理する |
| （任意）就活体験記 | 就職活動の体験記を共有する |
| （任意）OB訪問予約 | OB/OG訪問の予約調整を行う |

## 5. 非機能要件・制約条件

| 項目 | 内容 |
|---|---|
| インフラ環境 | 未定。学内サーバ／クラウド／既存研究室サーバのいずれか、基本設計工程で選択肢を提示し決定する |
| 技術スタック | 未指定。基本設計工程で提案する |
| 開発体制 | 一人開発を前提とし、保守性・学習コストの低い構成を優先する |
| セキュリティ | 研究室内限定利用のため、外部公開を前提としない認証・アクセス制御を検討する |
| 拡張性 | 将来的に利用者や機能が拡張される可能性を考慮した構成とする |

## 6. 基本設計工程での検討事項（未決定・要判断）

以下は要件定義段階では未決定であり、基本設計工程でトレードオフとともに選択肢を提示し、依頼者の判断を仰ぐ。

- 認証方式（学内アカウント連携 or 独自ログイン）
- 権限管理（教員／学生／見学者などのロール分け）
- 研究室HPとの連携方法（既存HPの技術構成に依存）
- サーバー監視データの取得方法（ログ収集・監視エージェント設置・手動報告等）
- ホスティング環境・技術スタックの選定
