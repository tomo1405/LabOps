## 2. システム構成（全体アーキテクチャ）

- 利用者（研究室メンバー）はブラウザから Web アプリケーションにアクセスする
- Web アプリケーションは認証機能と各機能モジュールを集約したモノリシック構成とする（一人開発・保守性を優先）
- Web アプリケーションはデータベース（PostgreSQL）と接続する
- 外部連携として、学内サーバ（研究室サーバ・学科サーバ）からリソース利用状況データを取得し、研究室HPへNews投稿を連携する

```
利用者（ブラウザ）
      │
      ▼
学内サーバ ── Webアプリケーション ── 研究室HP
（利用状況取得）  （認証＋各機能モジュール）  （News投稿連携）
      │
      ▼
   データベース
```

## 3. 技術スタック・インフラ（決定事項）

| 項目 | 選定 | 理由 |
|---|---|---|
| バックエンド | Python / Django | 標準の管理画面で事務・承認フローを素早く構築できる。学習コストが低く一人開発向き。学術分野での情報も豊富 |
| フロントエンド | Django テンプレート + Bootstrap + htmx（部分的な動的更新用）+ Chart.js（グラフ表示） | ビルドツール不要でシンプルに保守できる。SPA化による複雑さを避ける |
| データベース | PostgreSQL | 実運用に耐えるリレーショナルDB。Django との親和性が高い |
| ホスティング | 研究室サーバー上（Docker Compose：アプリ + PostgreSQL + nginx） | 追加コストなし。学内ネットワーク限定で公開範囲を制御しやすい |
| デプロイ方式 | Docker Compose | 環境差異を減らし、サーバー故障時の再構築や将来的な機材更新に強い |

## 4. 認証・権限方針（決定事項）

- 初期は Django 標準認証をベースにした独自ログイン（メールアドレス＋パスワード）で開始する
- 将来的に学内SSO（LDAP等）へ移行できるよう、認証バックエンドを差し替え可能な構成にしておく（`django-allauth` 等の利用を想定）
- ロールは「教員」「学生」の2種を基本とし、出張費申請の承認など一部機能は教員ロールに承認権限を付与する

## 5. 画面構成（サイトマップ）

- ホーム/ダッシュボード：お知らせ（学食メニュー・研究室News）、在室メンバー一覧
- 研究支援
  - 研究日記（一覧・詳細・新規作成）
  - 研究スケジュール（カレンダー/ガントビュー）
  - 学会準備（締切一覧・チェックリスト）
- 情報共有
  - 在室メンバー可視化
  - 学食メニュー共有
  - 研究室HP News投稿フォーム
- サーバー管理
  - 研究室サーバ利用状況ダッシュボード
  - 長期利用申請（申請フォーム・申請一覧・承認画面）
  - 学科サーバ利用状況ダッシュボード
- 事務
  - 出張費申請（フォーム・一覧）
  - 開発リクエスト（チケット一覧・新規作成・詳細/コメント）
- （任意）キャリア
  - 就活体験記一覧
  - OB訪問予約

## 6. データ構造（主要エンティティ）

| エンティティ | 主な属性 | 主な関連 |
|---|---|---|
| User | id, 氏名, 役割（学生/教員）, メール | 全機能の作成者として関連 |
| AttendanceStatus | user_id, 状態（在室/不在）, 更新日時 | User に1:1 |
| DiaryEntry | id, user_id, 日付, 本文, タグ | User に1:N |
| ScheduleEvent | id, user_id, タイトル, 開始/終了日時, 種別 | User に1:N、学会準備と紐付け可 |
| ConferencePrep | id, 学会名, 締切日, user_id, チェックリスト | User に1:N |
| Server | id, 名称, 種別（研究室/学科）, 設置場所 | 利用状況・申請の親 |
| ServerUsageSnapshot | id, server_id, 取得日時, CPU/メモリ/ディスク使用率 | Server に1:N |
| ServerLongTermRequest | id, user_id, server_id, 期間, 理由, ステータス | User・Server に1:N |
| CanteenMenu | id, 日付, メニュー内容, 取得元 | 独立（日付単位） |
| NewsPost | id, タイトル, 本文, author_id, ステータス, 公開日時 | User に1:N |
| TravelExpenseRequest | id, user_id, 出張先, 目的, 金額, ステータス | User に1:N |
| Ticket | id, タイトル, 説明, requester_id, ステータス, 優先度 | User に1:N |
| （任意）JobHuntingStory / ObVisitRequest | user_id, 内容/希望日, ステータス | User に1:N |
